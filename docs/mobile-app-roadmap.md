# App 路线

移动端路线优先 PWA，第二阶段再评估 Capacitor。React Native 和 Expo 暂缓。

## 产品定位

移动端适合：

- 快速提交短提示词。
- 从相册选择参考图。
- 查看生成进度。
- 收藏、下载和分享结果。
- 重试失败任务。
- 查看批量队列状态。

移动端不适合承载复杂服务商配置、长表单和大量参数对比。复杂配置仍以桌面或 Web 大屏为主。

## 阶段 1：PWA

PWA 是第一阶段，因为它复用当前 Web 应用，成本最低。

目标：

- 可添加到手机主屏幕。
- 启动后保持移动端布局。
- 静态资源可缓存。
- 离线时明确提示不能生成新图。
- 图片保存和分享先使用浏览器能力。

建议事项：

- 增加 Web App Manifest。
- 增加移动端图标和应用名称。
- 检查移动端底部输入栏、设置页和任务详情。
- 优化触摸目标和长文本换行。
- 保留当前 API 配置结构。

不做事项：

- 不加入原生权限。
- 不做后台生成。
- 不做离线生成。
- 不重写 UI。

## 阶段 2：Capacitor APK

当 PWA 已验证有稳定移动需求后，再评估 Capacitor。

适合加入 Capacitor 的触发条件：

- 用户明确需要保存到系统相册。
- 用户明确需要系统分享面板。
- 用户明确需要更稳定的文件选择。
- 用户明确需要系统通知。
- 项目能维护 Android 构建、签名和发布流程。

Capacitor 第一版只做宿主能力：

- 保存图片。
- 打开外链。
- 选择图片。
- 系统通知。
- 可选安全凭据存储。

核心生成、历史、收藏夹、批量逻辑仍复用 Web 代码。

## 暂缓路线

React Native 和 Expo 暂缓。

原因：

- 当前代码是成熟 Web 应用。
- 重写 UI 会增加大量维护成本。
- 生成逻辑、IndexedDB、画廊和设置都需要重新适配。
- 当前阶段更需要验证产品流程，而不是重建技术栈。

## runtimeHost 对齐

移动端也应复用桌面端文档中的 `runtimeHost` 思路：

- `kind: 'mobile'`
- `pickImages`
- `saveBlob`
- `openExternal`
- `showNotification`
- `secureCredentialStore`

PWA 可以先提供 Web 实现。Capacitor 后续替换宿主实现，不改业务层。

## 移动批量边界

移动端第一阶段只需要能查看和提交轻量批量：

- 显示变量数量。
- 显示批量提交按钮文案。
- 阻止遮罩批量。
- 显示运行中的任务状态。
- 失败项可在画廊中重试。

暂不做复杂批次编辑器、参数矩阵或后台队列。

## 验收标准

进入 Capacitor 前至少满足：

- PWA 可稳定安装和打开。
- 移动端主流程无明显遮挡和溢出。
- Gallery 批量在移动端可提交和阻止遮罩场景。
- 没有私有 API 地址、模型或凭据写入代码。
- Web 版本不因移动路线增加额外依赖。
